## Build and verification
- `build.ps1` uses the .NET 10 SDK and publishes a windowless, framework-dependent win-x64 app to `artifacts\app\sBridge.exe`. Keep all output files together. It resolves its own working directory; `sBridge.csproj` explicitly lists sources to exclude test/generated files. Add new application sources there.
- Windows root commands: `dotnet.exe restore .\sBridge.slnx --locked-mode`, then `dotnet.exe build .\sBridge.slnx -c Release --no-restore`, then `dotnet.exe test .\sBridge.slnx -c Release --no-build`. Focus codec/repository tests with `--filter "FullyQualifiedName~VdfParserTests|FullyQualifiedName~SteamShortcutRepositoryTests"`. Tests link production sources without loading the GUI; fixtures are synthetic, not Steam-captured. The real Windows sharing-violation test skips on other OSes.
- `global.json` rolls forward within stable .NET 10. Nullable is enabled; three legacy files have temporary file-local opt-outs. Keep new code nullable-aware. Current Windows build/publish has zero warnings. `.github/workflows/windows.yml` uses stable .NET 10 on Windows, warning-as-error builds, tests/TRX, both package modes and non-desktop smoke. Desktop and installed integrations remain opt-in. No source formatter is configured.
- OpenCode runs in WSL2. Use Windows `dotnet.exe`/`powershell.exe`, `wslpath -w`, and an explicit Windows working directory. Restore/build/test/publish from the UNC checkout were verified. Keep WSL paths out of product settings; pure-logic tests cannot validate COM, registry, WinForms, Appx, Steam, or SISR.
- After `build.ps1`, `powershell.exe -ExecutionPolicy Bypass -File .\tests\WindowsSmoke.ps1` checks JSON migration/save, unchanged legacy source, unsupported-schema rejection, locked-save reporting, and a SISR-disabled custom launch. Desktop scripts isolate state with `SBRIDGE_TEST_DATA_DIRECTORY` (absolute Windows temp path); never run them against normal LocalAppData. The override is test-only. GUI/controller checks require Windows; synthetic probes do not validate commercial games.
- `tests\WindowsOwnedSisrSmoke.ps1` checks external-process protection and cleanup before a launch-error dialog using a controlled stand-in. Installed-SISR tests skip unless `SBRIDGE_TEST_SISR_PATH` is set; focus `FullyQualifiedName~InstalledSISR` for legacy API lifecycle plus managed config/readiness. Both use no-Steam/non-resolving-VIIPER mode, not controller/first-run Steam setup validation. `tests\WindowsManagedSisrSmoke.ps1` needs the Release probe plus published app; it checks readiness before activation, managed cwd/config, graceful shutdown and unsupported-version cleanup before the error dialog with a controlled API stand-in.
- `sBridge.Tests` has a test-only executable entrypoint for argv capture/controlled chains; VSTest does not run it during discovery. `tests\WindowsLaunchArgumentsSmoke.ps1` and `tests\WindowsSessionSmoke.ps1` need the Release solution build plus published app. COM-string tests check Windows decoding, not COM activation. Native argument/session/SISR tests share a serialized integration collection and stage probes locally, avoiding UNC shell-launch hangs.
- `tests\WindowsGameIdSmoke.ps1` verifies stored UUID launch/argument capture, independent ID profiles, and missing-ID failure before activation/integration using temporary data. New-import VDF field regression tests link the pure SteamShortcutBuilder; live Steam import/readback is still unverified.
- `tests\WindowsDiscoverySmoke.ps1` uses Windows UI Automation to check responsive packaged scan/cancel, read-only Epic inventory scan, and close-during-scan cleanup. It requires an interactive desktop and published app. The native Appx inventory test is opt-in: set `SBRIDGE_TEST_PACKAGED_DISCOVERY=1`, filter `FullyQualifiedName~InstalledPackagedInventoryReadOnlyDiscovery`, then clear the variable. Normal runs skip it.
- Epic tests use synthetic `.item` files and a unique temporary HKCU test-protocol association, never Epic's real handler. The native test checks encoded URI delivery and PID-zero discovery of a controlled game after launcher exit. It does not validate Epic authentication, actual games, or anti-cheat. Keep registry/process cleanup scoped to those owned test resources.
- `tests\WindowsSteamAccountsSmoke.ps1` requires Steam closed and uses UI Automation with a synthetic Steam installation. It verifies empty-selection blocking, selected-only import, backup/first-file behavior, persisted checkboxes, and retry deduplication. `SBRIDGE_TEST_STEAM_DIRECTORY` requires isolated `SBRIDGE_TEST_DATA_DIRECTORY`; both must be absolute Windows temp paths and restored after tests. Never point the synthetic override at live userdata. Native junction tests use owned temporary directories and remove only their own junctions.
- Artwork tests use injected HttpMessageHandler responses, synthetic images, and temporary account files, never a real API key/network. Windows image tests load the Release application's actual processor and installed .NET 10 Desktop assemblies without changing the test project's portable target. `SBRIDGE_TEST_ARTWORK_UI=1`, filter `FullyQualifiedName~ActualSettingsQueueBoundsConcurrencyAndDefersCloseUntilCancelledJobsFinish`, enables an isolated STA settings/queue/close check with an injected hanging HTTP client. It restores test environment paths; normal runs skip it.
- `tests\WindowsDiagnosticsSmoke.ps1` checks read-only, responsive diagnostics against temporary app/data/Steam roots with a fake protected key. It verifies safe copy payload and enabled copy action without replacing the clipboard or writing integration/settings state. Diagnostic retention/redaction tests use owned temporary files; the real logging sharing-violation check skips off Windows.
- `package.ps1` stages Release win-x64 framework-dependent/self-contained output in fresh owned artifact folders, uses an explicit version (`0.0.0-dev` default) and optional revision, excludes state/tests/PDBs, includes GPL/runtime notices and payload hashes, then creates sorted timestamp-stable ZIPs/checksums in `artifacts\packages`. Keep all extracted files together; no trimming/single-file or SISR bundling. `tests\WindowsPackageSmoke.ps1 -Package <zip>` checks hashes/runtime layout and a temporary SISR-disabled launch; `-DesktopChecks` adds isolated GUI smoke. Invalid runtime roots on a SDK machine are not clean-machine proof. Do not commit/push/sign/publish releases without an explicit user request.
- `tests\PrepareWindowsSandbox.ps1` creates a local Windows temp bundle with read-only package/test inputs, a dedicated writable results mapping and a `.wsb` file; it does not enable features or launch/reboot. Optional redirection/network settings use Windows defaults. `WindowsSandboxVerify.ps1` rejects installed .NET 10, runs package/desktop smoke and writes result.json/transcript.txt. Do not map normal LocalAppData/Steam/checkout data. Require a successful guest result matching the package hash; host-side preparation is insufficient. The maintainer repaired Sandbox and launched the simplified .wsb manually through Win+R for the successful 2026-10-08 run. Enabling/repair/reboot remains user assisted.

## Wiring and contracts
- `Program.cs`, `SettingsForm.cs`, and `SteamShortcuts.cs` retain a global `partial class Program`; `SettingsForm` is nested and hand-built. `AppManager.cs` was replaced by nullable-aware `Providers/` adapters. Program owns startup/configuration/orchestration; providers own discovery/activation/evidence, not Steam writes, settings persistence, SISR lifetime, or monitoring. `SteamShortcuts.cs` uses `VdfParser.cs`, `Steam/SteamShortcutRepository.cs`, and `Steam/SteamShortcutIdentity.cs` for codec/persistence/identity.
- Provider launch routing uses explicit request kind; activation remains synchronous on the caller. `WindowsPackagedActivation` requires STA and declares native HRESULTs with PreserveSig. Discovery uses a unique BOM UTF-8 script and structured bounded JSON; stdout/stderr drain concurrently under a 60s budget. Cancellation stops only the retained discovery root. UI retains results on cancel/failure and defers close asynchronously until command/pipes/temp-script cleanup completes.
- Epic uses explicit `EpicLauncher` stored kind, full case-sensitive namespace:item:app identity, canonical percent-escaped URI, and no extra sBridge argument tokens (configure arguments in Epic Launcher). Game construction/JSON load rejects mismatched identities/targets or extra tokens before integration. Activation disposes any launcher handle and returns PID-zero evidence, never adopts/stops Epic Launcher. Discovery has 1 MiB/file, 4096 manifest, and 30s cooperative budget limits; no recursive executable search. Relative executable hints must stay within the absolute Windows install directory. Malformed files warn; conflicting identity/install evidence is omitted. Credit Luke1505's PR #1.
- No arguments opens settings. Legacy packaged-game arguments are `<AUMID> [executable_hint] [game_args...]`; custom launches use `"<exe_path>" [game_args...]`. The second packaged-game argument is a process hint, not a game argument. Keep shortcut construction and `Main` parsing in sync; preserve quoting when forwarding arguments.
- `Launching/LegacyLaunchRequest.cs` preserves classification, slash normalization, hint positions, and decoded argument tokens. Win32 uses its `CreateWin32StartInfo`/BCL `ArgumentList`; COM uses `WindowsCommandLine.Join`. Do not rejoin decoded args with spaces. `LegacyLaunchOptions` builds only LaunchOptions; leave bridge Exe/AppID quoting unchanged. UI custom argument text stays raw; an empty packaged hint needs a `""` placeholder before game arguments.
- `Core/AppSettings.cs` and immutable `GameProfile` values replace the old parallel dictionaries. `SteamInputMode.Automatic` means inherit the global SISR choice, not disable. Reads do not create profiles; removing an integration override retains a watch-only profile, and clearing watch retains an explicit integration override. Legacy target keys remain unquoted/case-insensitive; use `ParseFirstArgument` for quoted paths.
- `Core/Game.cs` stores immutable UUID/provider/explicit-kind/target/argument/hint/install metadata in the optional schema-1 `games` section of config.json, atomically with UUID profiles. GameCatalog deduplicates provider identity + launch kind + exact argument tokens (Windows identity case/slash aware); names/hints can update without new UUIDs. Argument variants are distinct. Registration rollback covers registry/profiles on failed persistence; commit before constructing `launch <id>` VDF entries.
- GameLaunchCommand owns strict `launch <D-format UUID>` dispatch/resolution; invalid/unknown IDs fail before SISR or activation. Stored kind bypasses legacy filename heuristics; profile keys are UUIDs for ID launches and legacy targets for legacy launches. UI resolves modern shortcuts with ShortcutProfileKey/ShortcutTarget, not ParseFirstArgument (`launch` is a verb, not a game key). Existing shortcuts are not rewritten; removal retains local registrations.
- GUI settings auto-save. Preserve the `isUpdatingUi` guard when populating controls so change events do not write unintended per-game overrides.
- `Sessions/GameSessionMonitor.cs` consumes/disposes the initial observation handle, never kills games, and owns multi-hop decisions. `GameLaunchEvidence` carries baseline/UTC/hints; `ProcessMatcher` rejects prelaunch/unknown-creation/retired/helper matches and near-ties. Track PID plus creation time; retained ancestor exit times prevent stale parent-PID adoption. Windows observation uses Toolhelp/limited image queries/visible windows in the current session.
- Monitor defaults: 1s scan, 90s provisional/PID-zero discovery, 3s matched-game exit grace, 32 handoffs, 10m live provisional timeout. No global game-duration cap. Keep monotonic wait budgets and cancellation; do not restore first-match or name-only adoption of pre-existing processes. Watch overrides should name the real game; real protected/service-launch chains still need validation.
- Keep STA-sensitive COM activation explicit during async migration; an async entrypoint continuation is not guaranteed to remain on an STA thread.
- `Program.Main` owns `SisrProcessManager` inside an inner `try/finally`, so cleanup runs before the outer exception dialog. Keep activation on the STA entrypoint; monitoring/owned cleanup use async internals after activation. Not-found/ambiguous/limit results are errors, not unconditional successful sessions.

## Persistence and integration gotchas
- `Configuration/AppPaths.cs` defaults to `%LOCALAPPDATA%\sBridge\config.json` and `logs\sBridge.log`; no current writes beside the executable. `sBridge.cfg` beside the executable is migration input only. Its original/backup/comments/unknown settings are retained untouched; existing JSON wins and does not reimport later legacy edits. Per-user state is shared across executable copies, not selected from each working directory.
- `JsonSettingsCodec` uses schemaVersion 1, strict required fields/typed modes, 4 MiB limits, duplicate rejection, and JSON extension preservation. `JsonSettingsStore` validates/decrypts temporary bytes, stages backups, rejects stale/deleted/denied originals, and uses non-overwriting creation/atomic replacement. Invalid JSON/schema/credential must never fall back to legacy/defaults or be overwritten. Legacy source changes during first migration abort it safely; unknown legacy fields remain in the source file, not JSON.
- `WindowsSecretProtector` uses current-user DPAPI with no UI/machine-wide flag or extra package. The protected SteamGridDB blob is inside the same atomic JSON document; plaintext exists only in memory/new UI input. Retained `.cfg`/`.cfg.bak` may still contain plaintext. Unchanged keys reuse ciphertext; never log/copy decrypted keys or claim portability to another Windows user. Actual DPAPI tests skip on non-Windows.
- `LegacyConfigurationCodec`/`LegacyConfigurationStore` remain for migration/compatibility tests (first `=` split, strict BOM decoding, comment/unknown-key retention); do not resume legacy writes in startup. Program.Settings remains transitional with visible save errors/modal deduplication. Keep isUpdatingUi in SavePaths/population; nested saves during an error dialog are suppressed. Format restrictions belong in the codec; JSON supports `=` paths. A concurrent first creator loads the validated winning JSON, never overwrites it or merges legacy settings.
- Close Steam before modifying `shortcuts.vdf`: Steam can overwrite changes on exit. `SteamAccountDiscovery` reads names via bounded text VDF and inventories nonzero numeric userdata directories, including first-file accounts. Optional schema-1 `selectedSteamAccountIds` persists explicit choices; old state starts empty. Empty, unavailable, or ambiguous selections block imports/migration, never mean all. Discovery displays all rows with account IDs; removal stays limited to checked rows' original documents. `SteamShortcutImporter` deduplicates per account and reports independent failures; retries skip already-saved copies. Credit Luke1505's PR #1.
- Edits must retain the loaded `SteamShortcutDocument` snapshot; saves reject stale/missing/unreadable/malformed originals and a running Steam process. The repository validates same-directory temp bytes, stages `.bak`, then uses `File.Replace`; unsupported atomic replacement fails closed. Consume per-file save results, including partial account failures; never show unconditional success or recreate a file after a load error.
- Only `LoadForImport(SteamAccount)` prepares an explicit absent-file snapshot on FileNotFound/DirectoryNotFound. Save requires an existing numeric account, rejects linked userdata/account/config, and creates only its config directory. Validated first-file temp bytes commit via non-overwriting `File.Move`, without a new backup or replacement fallback. A concurrent creator is left intact; after success the document becomes an existing-file snapshot. Deleted loaded originals never switch to creation. These are optimistic path checks, not cross-process edit merging or a junction-race proof.
- Artwork uses a shared redirect-disabled HttpClient, typed API envelopes, API-only Bearer headers (never CDN headers), HTTPS/default-port URL validation, 3 attempts, Retry-After <=10s (longer values fail without early retry), 20s/request and 2m/job budgets, 1 MiB JSON/16 MiB images, and 16M-pixel bounds. The UI owns at most 32 pending jobs with two active and cancels/awaits work on close. Job warnings are separate from shortcut save results. Secrets/server bodies/signed image URLs are not logged.
- New imports initially store an empty icon. Jobs capture stored AppID/Exe/LaunchOptions/name, not recomputed identity. PNG/JPEG bytes are decoded by Windows GDI+, icon output is actual bounded PNG, and file extensions come from content. Grid writes are same-directory staged/non-overwriting with account/config/grid link checks; existing art is retained. Only validated icon results can reach `SteamArtworkIconUpdater`, which reloads, checks exact unique identity/original icon, and uses normal repository saves; Steam running, changed selection/icon, deleted/malformed files or ambiguity block updates. No worker mutates a shared VDF document. Existing-art repair, match selection UI, and WebP remain separate work.
- `shortcuts.vdf` is binary VDF: strict UTF-8 NUL-terminated strings, map/string/Int32 tags. Unknown tags are rejected, not discarded. Limits are 32 MiB/file, 1 MiB/string, 64 map-depth levels, 100,000 elements. Reads accept root-close alone or one extra `0x08`; saves emit both. Preserve unrelated fields and stored IDs. Use fixtures/temp files, never live userdata, in tests.
- Current shortcut AppIDs are CRC32 of the quoted bridge executable path plus app name, OR'd with `0x80000000`; artwork filenames use that ID. Preserve stored IDs/artwork associations. Stable sBridge UUIDs are separate; do not casually recompute Steam identity after quoting, rename, or relocation changes.
- UWP scanning runs an embedded script via `powershell.exe` (`Get-AppxPackage`, manifests, and `Get-StartApps`); UWP launching uses COM `ApplicationActivationManager` from the STA entrypoint.
- SISR startup retains the actual process handle and a per-user/session semaphore lease; an existing SISR or managed lease blocks competing startup and is never adopted/stopped. Keep legacy SISR arguments/cwd/Steam environment. Do not add name-based/process-tree kills or blanket Steam resets. SISR cleans its own VIIPER on normal shutdown; forced owned-root termination can leave integration cleanup incomplete.
- `WindowsSisrShutdown` and `WindowsSisrStatus` share `OwnedSisrHttp`: loopback listeners by owned PID, post-connect ownership verification before HTTP, redirects/proxies disabled, 64 KiB buffered responses. Quit remains version checked. Managed readiness has 15s total, 2s/request, 250ms polling and at most eight candidate listeners; only the verified API/version plus readable Steam status gates activation. Status reads version/Steam/VIIPER/devices/config, reports counts and whitelisted controller type, and never logs passwords, device identifiers, paths or raw bodies. No controller is required. Default binding is `localhost:0`, not 6400; file versions may be 0.0.0.0.
- Optional schema-1 `managedSisrStartup` defaults false. Legacy startup keeps raw arguments/cwd/environment. Managed startup creates per-session LocalAppData `sisr/sessions/<guid>/startup.json` and SISR.log with a controlled cwd; Kong v1.16.1 JSON uses flag keys (`api.listen_address`, `log.file`, `window.fullscreen`, `window.show`), not API config DTO names. Reject conflicting config/API/log flags before starting; override only inherited SISR_CONFIG/API/log env values, preserve Steam/controller context and other advanced tokens. Managed config/logs are retained for diagnostics, with no secrets copied from arguments. API readiness failures clean the owned root in Program's existing inner finally before any game activation/error dialog. Full profile/Steam Input isolation, startup setup and real-controller validation remain planned.
- `Diagnostics/BoundedLog` keeps 2 MiB active plus three archives, capped entries, UTC/bridge-ID/PID context, known-key/credential-option redaction, escaped newlines and named-mutex write coordination. Logging stays non-fatal; failures are counted. Raw local logs can contain paths/titles/ordinary args, so Copy Diagnostics exports only typed summary fields, never raw logs.
- New managed sessions own `.sbridge-session` marker handles and atomic <=4 KiB status summaries. Retention prunes only marked, unlocked, phase=ended, known-content non-linked folders: eight completed sessions and 4 MiB/completed SISR log. Starting/ready/cleanup-incomplete, unmarked older folders and unknown files are retained, protecting possible orphan roots. Active third-party logs are not capped in place. Status summaries use canonical versions/whitelisted types, no passwords/paths/device IDs. Diagnostics refresh runs off the UI thread, does not create/start/probe/mutate integration, and labels status as historical.
